# Webhook Contract — `POST /webhooks/signal`

The single ingestion endpoint used by the Hugging Face Space to deliver
approved signals to the AtlasSignals Relay.

## Endpoint

```
POST https://<your-deployment>/webhooks/signal
```

## Required headers

| Header                | Value                                            |
|-----------------------|--------------------------------------------------|
| `Content-Type`        | `application/json`                               |
| `x-atlas-signature`   | hex HMAC-SHA256 of the **exact raw request body** |
| `x-atlas-idempotency-key` | (optional convenience) same value as the body field |

## Signature algorithm

```
signature = hex( HMAC_SHA256( key = WEBHOOK_SECRET, message = raw_body_bytes ) )
```

- `WEBHOOK_SECRET` is shared between the Space and the Relay. It MUST be
  identical in both environments.
- The signature is computed over the **exact bytes sent** — do not re-serialize
  JSON before signing (key order and whitespace must match what is sent).
- The backend compares in constant time (`timingSafeEqual`).

## Request body (canonical signal event)

```json
{
  "signal_id": "3f2c2c3a-1b2c-4d5e-8f90-abcdef123456",
  "symbol": "XAU/USD",
  "direction": "BUY",
  "timeframe": "15M",
  "entry": 3365.42,
  "stop_loss": 3358.10,
  "take_profit": 3378.90,
  "confidence": 84,
  "setup_name": "TIER_A_HIGH_QUALITY",
  "market_state": "TRENDING_UP/TRENDING",
  "analysis_version": "ITER_32",
  "created_at": "2026-08-07T06:15:00.000+00:00",
  "idempotency_key": "9f2c...64hex",
  "metadata": {
    "setup_tier": "A",
    "sweep_type": "SSL_PDL",
    "sweep_reclaim": true,
    "execution_type": "MARKET",
    "bar_time": "2026-08-07T06:15:00.000+00:00"
  }
}
```

### Field rules

- `signal_id` — UUID v4 generated by the Space per event.
- `direction` — `BUY` or `SELL` (the engine's `LONG`/`SHORT` is mapped).
- `confidence` — integer 0–100 (engine `opportunity_score` × 100).
- `created_at` — ISO-8601 with UTC offset (`z.string().datetime({ offset: true })`).
- `idempotency_key` — ≥ 8 chars, content-derived: same engine signal → same key.
- `metadata` — optional, any shape; preserved in `raw_payload` (JSONB).

## Success response

`200 OK`

```json
{
  "received": true,
  "signal_id": "3f2c2c3a-1b2c-4d5e-8f90-abcdef123456",
  "inserted_at": "2026-08-07T06:15:00.123456+00:00"
}
```

## Error responses

| Code | Body                                            | Meaning                                  |
|------|-------------------------------------------------|------------------------------------------|
| 401  | `{ "error": "invalid_signature" }`              | Missing / wrong `x-atlas-signature`      |
| 409  | `{ "error": "duplicate_idempotency_key", "signal_id": "<uuid>" }` | Same signal already stored |
| 422  | `{ "error": "invalid_payload", "details": {...} }` | Zod validation failed            |
| 500  | `{ "error": "internal_error" }`                 | Database failure (transient — safe to retry) |
| 503  | `{ "error": "server_not_configured" }`          | `WEBHOOK_SECRET` not set on the backend  |

### Retry semantics (sender side)

- Retry only on network errors / timeouts / HTTP 5xx.
- Do **not** retry on 4xx (401/409/422 are permanent).
- Because `idempotency_key` is content-derived, retries can never create
  duplicates — the backend answers `409` if the signal already exists.
